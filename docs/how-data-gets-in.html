How data gets in

Every fact starts in someone else's system. This is the road in: where data lives, how it travels, what the front door does to it, and which tables it lands in. Everything runs on synthetic data and local or sandbox services.

2How it travels

Batch: daily files

837, 835, 999, 277CA and the PM's CSV feeds land in a folder. The daily loader picks them up in a set order.

Live: events

A watcher polls the EHR every few seconds. A new booking starts a coverage check straight away, then again 3 days and 1 day before the visit.

Bots that ask

Bots send a 270 (eligibility), 276 (claim status) or a corrected 837 to the clearinghouse. The answer comes back as a file the same loader reads.

Safety on the roadClients refuse any non-local address unless a flag is set. Keys come from environment variables only. Nothing talks to a real payer.
→

3The front door (ingest)

1Parse and map. Read the X12 segments, FHIR resources or CSV columns into our fields.
2Hash identities. Patient and member numbers become salted hashes at this boundary. Raw ones never land in a table or a log.
3Never twice. A file is skipped if its hash and its control numbers (ISA13, GS06, ST02) were already loaded.
4Stamp every row. Tenant, source, known_at, loaded_at, and a flag if the row was rebuilt from other data.
5Record the fallback. data_feed notes which feed and fallback step each table runs on, so a missing feed shows as "unavailable", not zero.
6Fail safely. A file that does not parse is marked failed with a reason, and nothing half-loaded is stored.
→

What is still ahead

  • The loader fills the earlier data model. The 57-table canonical model is the design target, and wiring the loader to it is the next piece of work.
  • A real EHR's FHIR API will differ in profiles and permissions (SMART on FHIR). Not tested yet.
  • Stedi: only eligibility is verified live. Claim status and claim submission have not been run on the sandbox.
  • HL7 v2, payer portals and contract reading are not built, and contract reading needs an approved BAA first.
